# 07 — Risks and Open Questions

## Risks

| ID | Risk | Impact | Likelihood | Mitigation / owner task |
| :--- | :--- | :--- | :--- | :--- |
| R-01 | Windows refuses to load a third-party, non-driver-packaged APO on a capture endpoint (protected audiodg, policy, "audio enhancements" off, Win11 driver-bundled APO model). | Blocks D-004 | Realized (superseded by D-018) | T02 tested `apo_spike.dll` on Win11 Build 26300 (dynamic mic `fifine Microphone` + headset `AB13X USB Audio` with `VocaEffectPack`) via `FxProperties` SFX + `Restart-Service audiosrv -Force`: `audiodg.exe` never loaded the unsigned COM DLL (`OpenFileMappingW` `0x80070002`). **D-018** supersedes D-004 with virtual-cable output from `tine-engine`. |
| R-02 | Code signing: unsigned DLL/installer triggers SmartScreen; may be required for audiodg loading. | Install friction / blocker | Medium (mitigated for audio path by D-018) | T02 showed `audiodg.exe` did not load the unsigned SFX COM DLL on Win11 26300 (no CodeIntegrity event; `FxProperties` SFX path ignored). | R-03 | A bug in `tine_apo.dll` crashes `audiodg.exe` → **all system audio stops**. | Severe UX + reputation | Medium | `catch_unwind` at every COM boundary, no-panic lints, NaN latch, fuzz tests on `process()`, long soak tests, pass-through on any fault. |
| R-04 | Rune's `release_gpu_when_closed` leaves residual GPU/driver memory, or the windowless app + tray idle above budget. | Breaks "zero idle VRAM" | Realized in-process (mitigated by D-017) | T03 proved DX12/NVIDIA driver stays resident in-process after close (14.7–15.7 MB GPU dedicated, 12.2–15.2 MB shared, 85–174 MB WS). | R-05 | Vendor SFX/MFX APOs (Realtek, Nahimic, Dolby, NVIDIA Broadcast) already on the endpoint. | Lost vendor effects or double processing | High | Wrap the original APO CLSID (Equalizer APO pattern); store originals for clean uninstall. |
| R-06 | Windows Update / driver update resets FxProperties. | Tine silently stops | High | Startup + device-change health check; one-click repair. |
| R-07 | Endpoint shared-mode format is not 48 kHz / not mono. | Quality/latency | High | D-006 rate-agnostic DSP; downmix. |
| R-08 | Apps open the mic in **RAW mode** or exclusive mode (some games/DAWs) and bypass APOs. | Tine not heard in that app | Medium | Document; detect via the tap heartbeat not moving while the mic is in use? (best effort). |
| R-09 | `< 8 MB RSS` with the Rune runtime kept alive (state, text, layout caches) while the window is closed may be unrealistic. | Missed target | Resolved (D-017) | T03 measured: in-process Rune retained 85–174 MB WS after close; with D-017 (`tine.exe --ui` child), the idle tray+control parent is **1.74–1.88 MB Private Bytes / 9.25–9.53 MB Working Set** (0 MB GPU, 0.0% CPU). Realistic target updated to **< 12 MB Working Set (< 4 MB Private Bytes, hard 20 MB)** while closed. |
| R-10 | Rune is pre-release, accepts no PRs, and requires consumers to mirror its `[patch.crates-io]` (patched winit/wgpu-hal/parley/accesskit). | Breaking changes, build friction | Medium | Pin rev (D-012); bump Rune only in dedicated PRs that re-run headless snapshots and T03 checks; keep view state in plain structs; report bugs as Rune issues. |
| R-11 | RNNoise quality on music/singing or non-speech sounds; artifacts at high mix. | Quality complaints | Low | Mix control, Purity defaults ≤ 0.85. |
| R-12 | Shared memory DACL too permissive (any local process can change mic processing). | Local tampering | Low | Grant only interactive users + LocalService; validate/clamp every param in the APO. |
| R-13 | Limited test hardware (D-016): no condenser, laptop/webcam, Bluetooth, Realtek-jack or vendor-APO endpoint, and no spare machine/VM for the APO spike. | Bugs reach users on untested paths; a broken APO spike could silence the main PC | High | Restore point + registry export + Safe-Mode recovery script before T02; proxy fixtures; `tine diag`; community beta gate in T22 with a minimum coverage matrix. Borrowing a Windows laptop for one afternoon would cover laptop mic + Realtek + vendor APOs. |
| R-14 | GitHub Actions has never successfully run a job on this repo (Actions billing / spending limit is failing: every CI run since T01 fails in ~4 s with "recent account payments have failed"). `main` has therefore accumulated **red tests** that nobody noticed (two `stage_tone` tests broken since the T07 merge, one `stage_cleanup` test broken since the T08 merge — all fixed in T09). | "main always builds and passes CI" invariant is currently unverifiable; regressions ship silently. | Realized (since before T06). | Fix the GitHub billing/spending limit (maintainer, urgently); re-run CI on `main` after the T09 merge; optionally add a periodic `cargo nextest` self-check for agents. |
| R-15 | 21.6 ms added DSP latency (D-019) + virtual-cable routing (D-018) makes "Hear Myself" monitoring accumulate ~30+ ms of audible delay; latency-sensitive apps see a processed mic that lags. | Self-monitoring sounds like an echo; decouples lip-sync audio in recordings. | High | Document the latency in onboarding; consider a "low-latency mode" that bypasses the denoiser stage (drops ~960 samples, see D-019); benchmark the full `tine-engine` round trip in T15/T21. |
| R-16 | The Auto-Tune wizard overlay (T20) is contract-complete but integration-unverified: the capture runner that pushes mic blocks into `AutoCalibrator`, forwards `CalProgress`, latches `finish()`'s `Err(CalFailure)`, and replays the report's `changes` on `Intent::ApplyCalibration` lives in T16/T21 and doesn't exist yet. The UI adapter is proven only against synthetic fixtures (headless test + scenes). | The real hand-off (thread, block sizes, early-cancel, apply-replay) could reveal contract mismatches late; a review could mistake the green wizard for a working feature. | Medium | T16/T21 task files reference D-024 (adapter + `TODO(T11)` notes in `views/autotune.rs`); the adapter test already drives the real calibrator state machine, so any engine-side deviation from it fails `tine-ui::tests` before integration. |
| R-17 | Win32 named-pipe reply truncation: `DisconnectNamedPipe` discards un-drained bytes, so a pipe server that disconnects right after writing silently truncates any reply larger than the client's read slice (T17: `status` ~550 B failed while `meters` worked; the in-house diag ZIP EOCD overstated `cd_size` by 12 B and was rejected by standard readers — both now regression-tested). | Any future pipe/stdin protocol use (T21 `ui_bridge`, T22 QA tooling) can reintroduce truncation that only shows on large payloads; headless PTY sessions hide release-build CLI text, delaying discovery. | Medium (two instances already hit in T17) | Pattern is fixed in `single_instance.rs`: client sends one JSON line, server replies one line, then `FlushFileBuffers` before disconnect; client paces retries when the pipe doesn't exist (`ERROR_FILE_NOT_FOUND` → sleep). Verify archives with `python -m zipfile`; verify CLI output from a real console, exit codes from the shell. |

| R-18 | The "Hear Myself" latency badge is **partially nominal**: only the capture block duration is measured per callback; the WASAPI playback-side period (10 ms) is a nominal stand-in and the DSP term (21.6 ms, D-019) is a design constant — `cpal` does not expose `IAudioClient::GetCurrentPadding`, so the true end-to-end monitor delay is not observable through it. | Users hear ~10 ms more/less delay than the badge claims; latency-sensitive measurements mislead. | Low→Medium | Measure the playback padding via `IAudioClient` (Win32) or an impulse-loopback measurement in T21 (engine benchmark task) and fold the real value into the badge; document the badge as an upper bound in the UI until then. |
| R-19 | **RESOLVED — R-19 maintenance fix (PR `fix(dsp): work around rustfmt 1.99.1 deadlock in primitives/math.rs`).** The pinned toolchain's `rustfmt` (1.99.1 / rustfmt 1.10.0-stable) is **not deadlocked but exponentially slow** on deeply right-nested additive/multiplicative chains: formatting time grows ~8x per `+ r * (...)` nesting level (measured: depth 7→0.28 s, 8→1.4 s, 9→8.8 s, 10→54 s; the in-repo multi-line shape of `exp_f64`'s degree-11 Horner polynomial exceeded 240 s, i.e. an effective hang; the shallower 7–9-level chains in `ln_f64`/`sin_cos_f64` complete in ~0.5–2 s). | DoD runs (`cargo fmt --all --check`) could not complete; every agent had to skip formatting `tine-dsp`. | Medium (environment, all tasks) | **Fixed in place** (authorized maintenance of T05-owned `math.rs`): the three innermost Horner levels of `exp_f64` were extracted into a local `let high` — same evaluation order and association, public API byte-identical; verified **bit-exact over 6,591,389 comparison points** (pre-fix vs post-fix `exp_f64` compiled side by side: full [-720, 720] domain sweep + 1.4 M dense reduced-domain points, all `to_bits()` equal). rustfmt 1.99.1 now formats the file in ~5 s and `cargo fmt --all --check` exits 0 in ~5.3 s across the workspace. House rule while this rustfmt is pinned: keep `+ r * (…)` chains at most 8 paren levels deep (this is a rustfmt ~exponential width-search bug — report upstream to rust-lang/rustfmt). |
| R-20 | The "Hear Myself" latency badge **does not model the playback jitter-buffer headroom** (D-027): the monitor's end-to-end delay is ~60 ms higher than the formula's parts (measured capture block + nominal 10 ms period + 21.6 ms DSP), because the drift resampler deliberately holds `HEADROOM_CALLBACKS × callback` of buffered audio before rendering. | Users hear noticeably more delay than the badge claims (~100 ms real vs 41.6 ms shown); compounding with R-18 the badge under-reports by both the playback padding and the full headroom. | Medium (accepted trade for zero underruns, D-027) | Extend the badge formula with the headroom depth (callback size × `HEADROOM_CALLBACKS`, derivable from the negotiated rate) plus the R-18 impulse/padding measurement in T21; until then treat the badge as a lower bound. |
| R-21 | The dev machine's **default audio endpoints are SteelSeries Sonar virtual devices** (virtual mic + virtual sinks, default output at 96 kHz/8 ch) that drop `cpal` streams within seconds: the monitor soak's error callback fires and `stream_lost` trips at the first poll (~5–7 s), twice in a row. | Any ignored hardware test that uses `DeviceRef::Default` (monitor soak, devhost default runs) fails long before its acceptance window, wasting soak time and masquerading as a Tine bug. | Medium (environment; realized twice) | Pin physical endpoints for hardware tests via `TINE_HW_IN`/`TINE_HW_OUT` (e.g. `Microphone (AB13X USB Audio)` → `Speakers (AB13X USB Audio)`, verified stable); T16's soak evidently predated the Sonar setup or used stable devices — treat `stream_lost` at t≈5 s as a device problem, not a DSP problem. |
